# 数据建模、有限状态机与 LaTeX 算法推导 (Data, FSM & LaTeX Modeling)

## 1. 领域建模与数据存储设计 (Data Architecture)

### 1.1 关系型数据库 (MySQL) 规约
- **主键策略**：高并发场景优先 ULID / 分布式雪花算法，避免大批量写入页分裂；严禁业务字段做物理主键；
- **防重与唯一索引**：针对业务防重唯一索引（如订单号、支付流水号），软删除字段需采用 `delete_at = 0` 方案，确保唯一索引生效；
- **冷热分离与分表**：数据量预期突破千万级时，必须在方案中规划分表键（如按月分表 `_YYYYMM` 或按租户/用户 ID 哈希）。

### 1.2 缓存与状态存储 (Redis)
- **标准命名空间**：强制遵循 `{project}:{env}:{module}:{business_key}` 分层格式；
- **TTL 铁律**：所有缓存 Key 必须在方案中明确声明 TTL，杜绝永久 Key 污染内存；
- **防并发击穿/穿透**：高频热点数据设计互斥锁预热或逻辑过期，空结果显式设置 60s 短 TTL 防穿透。

## 2. 业务时序与有限状态机 (Workflow & FSM)

### 2.1 时序交互图规范 (Mermaid Sequence)
- 遵循 Mermaid 防崩渲染标准：参与者与节点名使用双引号包裹，连线说明使用清晰纯文本：
  ```mermaid
  sequenceDiagram
      autonumber
      actor User as "用户终端"
      participant GW as "API 网关"
      participant Order as "订单中心"
      participant Pay as "支付网关"

      User->>GW: 提交下单请求
      GW->>Order: 校验参数并预扣库存
      Order->>Pay: 创建预支付订单
      Pay-->>User: 返回支付拉起参数
  ```

### 2.2 有限状态机闭环 (State Machine)
- **正向流**：定义初始态、中间处理态与终态（待支付 -> 履约中 -> 已完成）；
- **逆向流**：明确超时取消、风控拦截、申请退款、退款成功的补偿跃迁；
- **防反向跃迁**：状态跃迁表必须声明合法前置状态，任何非法跳态强制拒绝并报警。

## 3. 复杂算法与数学模型 LaTeX 规范 (Mathematical Rigor)

方案中涉及计费公式、评分权重、限流漏桶或加权调度时，**坚决禁止使用自然语言模糊带过，必须使用标准 LaTeX 公式进行数学推导**：

### 3.1 格式与排版
- **行内公式**：使用 `$公式$`，例如加权耗损计算 $W_i = \alpha \cdot C_i + (1 - \alpha) \cdot R_i$；
- **独立公式块**：使用 `$$ ... $$` 独立居中：
  $$S_{final} = \sum_{i=1}^{n} w_i \cdot \frac{x_i - \min(X_i)}{\max(X_i) - \min(X_i)}$$

### 3.2 严密性要素
1. **定义域说明**：声明变量类型与范围（如 $w_i \in [0, 1], \sum w_i = 1$）；
2. **极值与边界处理**：明确除数为 0 时的降级极值（如 $\max(X_i) = \min(X_i)$ 时的取值定义）；
3. **数值溢出防范**：在方案中指明计算精度（如涉及金额计算，统一以“分”为整型单位或使用 `decimal` 库）。
